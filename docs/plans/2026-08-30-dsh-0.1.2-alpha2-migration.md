> 对象：上游 tag `dsh-v0.1.2-alpha.1` (cd5ef81481) → `dsh-v0.1.2-alpha.2` (0a53fb55be)，234 commits。
> 插件版本：0.3.0（单包 client/UI 插件，预构建 `lib/` 策略）。
> 本文证据均来自只读 `git -C D:/Projects/deepseek-harness/dsh show/diff/grep/log` 命令与插件源码逐行核对；dsh/ 目录零写入。

## 结论

**✅ 直接可升 —— 零代码改动。** 本插件只消费 keyed slot `tool.call.toolview` 的注册契约（`ToolCallViewProps` / `ToolCallOwnerProps`）、ui-slots 的 `PropsLocale`/shadow 规则、ui-chat 契约类型（`ToolCallBlock`/`ChatNodeStore` 等）与 ui-primitives 的卡片原语，这些面在 alpha.2 全部未变；alpha.2 唯一的注入契约破坏（`connectionGeneration` → `hostInfo`）恰好落在本插件**没有**使用的那条路径上。

2. **本地三件套验证**（workdir = 插件目录）：
   ```powershell
   Push-Location D:\Projects\deepseek-harness\dsh-plugin-merge-tool-calls
   pnpm run typecheck    # 经 node_modules junction 直接编译 alpha2 类型——本次迁移的类型试金石
   ```

## 升级后验证清单

以下验证需在 **dsh web 进程重启 + 浏览器硬刷新（Ctrl+Shift+R）之后** 进行：

1. **加载健康**：DevTools Console 无 `Failed to load plugins … missed the module table`、无 `Cannot find package '@deepseek-ai/dsh-client-*'`（若出现且指向 `@huanlin/*`，说明 client bundle 外部解析失败，而非 dsh 问题）。
2. **合并主路径**：让模型连续 `read` 3 个文件 → 应显示 `Read · 3 Files` 主卡 + 3 条 `└` 子行，点击主行动画展开/收起，子行可独立展开内容；`grep`+`glob` 相邻混排应合入同一张 `Search · n Queries` 卡；连续 `bash` 显示 `Bash · n Commands` 与终端卡。
3. **单次/打断语义**：单独一个 `read` 保持原单行（路径为可点击链接，展开内容卡）；两个 `read` 之间插入其他节点（如一条助手文本）则各自保持单卡。
4. **文件链接**：子行路径点击 → 侧边栏预览打开；`grep` 的目录型摘要不可点。
5. **状态语义**：让一次 `read` 失败或中断 → 主行摘要回退错误首行/警告点；`bash` 非零退出码 → 红点。
6. **截断不丢调用**：配置 `maxGroupSize: 2` 后连续 5 个 `read` → 应为 `2+2+1` 三组，无调用丢失。
7. **收起座位**：合并组的非组首座位不占流空间（依赖 `:has()` 规则，Chrome 105+）——流中间不应出现空洞空行。
8. **视觉差异核对（已知项）**：alpha2 起内置 ToolRow 的 diff 行折叠摘要带 `+n −m` 统计后缀；本插件的合并 diff 行（`write`/`edit`）**没有**该后缀（`src/client/rows.tsx` 的 RowCard 未引入 `diffTotals`）。功能无损，是否跟进对齐待人工确认。
9. **零源码 patch 复核**：`git -C D:/Projects/deepseek-harness/dsh status` 干净。
